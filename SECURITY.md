# Security Policy

Security issues in DigiX Lab may affect authentication, tenant isolation, workflows, or uploaded files. Please report suspected vulnerabilities privately so they can be investigated before details are made public.

## Supported versions

DigiX Lab is under active development. No supported release versions or security-update schedule have been announced. Reports affecting the current codebase are welcome; fixes for older versions are not guaranteed.

## Reporting a vulnerability

1. If this repository has GitHub private vulnerability reporting enabled, use **Security → Report a vulnerability** on the repository page.
2. If that option is unavailable, contact a project maintainer through a private channel listed on their GitHub profile. If you cannot find one, open an issue **only to request a private reporting channel**; do not include vulnerability details.

Include the affected component and version or commit, steps to reproduce, the potential impact, and a minimal proof of concept if possible. Remove secrets, personal information, and real tenant data from the report. Please do not test against systems or accounts you do not own or have permission to assess.

Do not post exploit details, credentials, or sensitive logs in a public issue or pull request. Allow the maintainers time to investigate and coordinate disclosure before publishing technical details.

## What to expect

Maintainers will review reports and respond as soon as practical. If confirmed, they will assess the impact, prepare a fix, and coordinate disclosure with the reporter. No fixed response or remediation timeline is currently promised.
